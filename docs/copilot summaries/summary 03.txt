1. Core Requirements
Kaleido is metadata-driven, not a traditional CRUD or workflow framework.
Queryable API surface should be generic and registration-driven, not controller-per-record.
Goal is to provide an HTTP-accessible Queryable surface without exposing the strongly-typed internal implementation details.
Support:
Record discovery
Metadata discovery
Query execution
Named query execution
Query parameter discovery
Internal framework remains strongly typed.
External API remains runtime/metadata driven.
Consumers should not need to build:
CustomerController
ProviderController
MemberController
etc.
Query metadata returned to consumers must include:
Fields
Search/filter capabilities
Paging capabilities
Named queries
Named query parameters
2. Architectural & Component Decisions
Queryable.AspNetCore
Purpose

Kaleido.Queryable.AspNetCore owns:

HTTP endpoint surface
HTTP contracts
Endpoint discovery
Query execution transport layer

It does not own:

Record definitions
Query execution
Query metadata generation

Those remain in Kaleido.Queryable.

Endpoint Strategy

Consumer usage:

builder.Services
    .AddKaleido()
    .AddQueryable()
    .AddQueryableAspNetCore();

app.MapKaleidoQueryableEndpoints();


Optional:

app.MapKaleidoQueryableEndpoints(options =>
{
    options.RoutePrefix = "/reference-data";
});

Default Routes

Preferred initial routes:

GET  /kaleido/queries
POST /kaleido/queries/{key}


Reasons:

Queryable owns "queries"
Queryable does not own general "registrations"
Future Process registrations can coexist
Metadata Ownership

Major architectural decision:

Metadata owns NamedQueries

Conceptually:

Record Metadata
 ├─ Fields
 ├─ Pageable
 └─ NamedQueries


Consumers should receive a complete metadata picture.

MetadataBuilder Does NOT Own NamedQuery Discovery

Refactor decision:

RecordMetadataBuilder should only build metadata directly available from the Record Type:

Record attributes
Fields
Pageable configuration

It should NOT:

Discover named queries
Scan query implementations
Resolve parameter definitions

Reason:

Named query metadata comes from:

IQueryableRecordNamedQuery<TRecord>


implementations, not record attributes.

Registration Assembly Owns Aggregation

Responsibility split:

Discovery
    ↓

Records
Sources
NamedQueries

    ↓

Registration Assembly

    ↓

RecordMetadata


Registration building combines:

Record Metadata
+
Named Query Metadata


into one complete metadata object.

Named Query Architecture
Original Design
string QueryName
IReadOnlyDictionary<string, object?> Parameters


Problem:

Two fields represent one concept.
Parameters only make sense when QueryName exists.
New Design
public record KaleidoQueryRequest
(
    KaleidoNamedQuery? NamedQuery,
    KaleidoQueryBody? Query
);

public record KaleidoNamedQuery
(
    string Name,
    IReadOnlyDictionary<string, object?>? Parameters = null
);


Benefits:

Better domain model
Stronger ownership
Future extensibility
Named Query Metadata

Query metadata became discoverable:

public sealed record NamedQueryMetadata(
    string Name,
    string Description,
    IReadOnlyList<QueryParameterMetadata>? Parameters = null
);

Query Parameter Metadata

Final shape:

public sealed record QueryParameterMetadata(
    string Name,
    Type Type,
    bool Required,
    string Description
);

Query Parameters Live On Query Implementation

Final interface direction:

public interface IQueryableRecordNamedQuery<TRecord>
    where TRecord : class
{
    IReadOnlyList<QueryParameterMetadata>? Parameters { get; }

    IQueryable<TRecord> Apply(
        IQueryable<TRecord> query,
        KaleidoNamedQuery namedQuery);
}


Reason:

Avoid duplication between:

[KaleidoAllowedQuery]


and a separate descriptor object.

Attribute Ownership

Attribute owns:

Name
Description


Query implementation owns:

Parameter definitions


Result:

No duplicated metadata.

Query Parameter Identification

Problem:

typeof(SampleKaleidoRecord.Category)

Parameter Type represents parameter value type:

typeof(string)

RecordMetadata


stores:

directly,

or whether registration separately owns:

RecordMetadata
+
