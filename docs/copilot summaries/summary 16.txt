1. Core Requirements

Preserve the original intent of the runtime architecture:

ExecutionProcessor orchestrates execution.
IStepExecutionEvaluator determines execution decisions.
IProcessStateUpdater only mutates/persists process state.
Availability determination should not live inside the state updater.

Continue providing AvailableSteps to handlers via ProcessStepContext.

This is required so framework consumers (developers implementing handlers) know what steps are legal candidates when returning RequiredStep.
Handlers should not need to understand process graphs.

Introduce process availability windows:

Support:
AvailableAfter
AvailableUntil
Availability is determined from process history (completed steps), not external state.

Avoid introducing a separate process-state model (e.g. CartOpen, CheckedOut, etc.).

Completed step history remains the source of truth.
Do not require developers to manually synchronize process state with process execution history.

Maintain startup-time discovery:

Reflection should occur during registration/startup.
Runtime execution should operate entirely on pre-built metadata.
