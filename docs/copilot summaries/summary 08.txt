1. Core Requirements
Build a metadata/business-driven process framework, not a BPM/workflow engine.
Keep orchestration logic minimal; push behavior into dedicated components.
Persist process state after execution so requests can be safely retried.
Never re-execute a step that has already been successfully completed with the same request values.
Allow consumers to submit:
a single step,
multiple steps,
the entire process at once.
Support strongly typed step contracts.
Use hydrated step instances throughout the pipeline as early as possible.
Support:
primitive types,
nullable types,
enums,
collections,
nested/complex objects.
The framework must distinguish:
request/data problems,
process consistency problems,
framework/developer defects.

  "SelectProcedure": {

Prevents duplicate step requests.
Better represents "step → values".
Aligns naturally with planner lookup behavior.
