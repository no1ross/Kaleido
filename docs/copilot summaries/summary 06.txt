1. Core Requirements

Keep Queryable transport-agnostic.

Queryable should operate on strongly-typed CLR values.
Queryable should not know about:
JsonElement
ASP.NET Core model binding
JSON serialization details
HTTP transport concerns

Preserve strict validation inside Queryable.

Named query parameter validation should remain strongly typed.
Invalid parameter types should fail validation.
Queryable should not silently stringify or broadly coerce values.

Allow only intentional compatibility conversions.

Numeric compatibility should be supported:
int -> decimal
int -> decimal?
int -> long
similar numeric widening scenarios
Nullable lifting should be supported.
Enum string parsing may remain supported where appropriate.
Arbitrary conversions such as:
123 -> "123"
Guid -> string
DateOnly -> string
broad Convert.ChangeType() behavior
are not desired.

Move JSON-related conversion responsibility into the ASP.NET Core layer.

ASP.NET should normalize request values before Queryable receives them.
2. Architectural & Component Decisions
Queryable Layer
QueryRequestValidator

Responsibility remains:

named query validation
required parameter validation
allowed parameter validation
parameter type validation
filter validation
search validation
sort validation
paging validation

Decided that:

required parameter enforcement belongs in Queryable
unexpected parameter enforcement belongs in Queryable
metadata-based validation belongs in Queryable

Rejected moving these responsibilities into ASP.NET Core.

Supported Runtime Types
Added concept of validating supported CLR runtime types.
Preferred approach:
Use DataTypeMapper as the source of truth.
Queryable should throw if unsupported runtime types arrive.
Goal:
Catch transport leaks such as:
JsonElement
framework-specific types
arbitrary complex objects
Queryable should only operate on supported CLR scalar types.

QueryNormalizer

Introduced normalization layer.

Responsibilities:

Named Query Parameter Normalization

Input:

IReadOnlyDictionary<string, object?>


plus:

QueryParameterMetadata


Output:

IReadOnlyDictionary<string, object?>


containing normalized CLR values.

Uses:

ValueConverter.Convert(...)


at the transport boundary.

Filter Normalization

Input:

QueryBody


plus:

RecordMetadata


Output:

QueryBody


with normalized filter values.

Uses field metadata to convert values to correct CLR types.

Endpoint Mapper Changes

Changed endpoint mapping so metadata is available during normalization.

Query Endpoint

Previously:

MapTypedQueryEndpoint(
    string recordKey)


Now:

MapTypedQueryEndpoint(
    RecordRegistration record)


Allows:

record.Metadata


to be used during normalization.

Named Query Endpoint

Previously:

MapTypedNamedQueryEndpoint(
    string queryName)


Now receives:

NamedQueryRegistration namedQuery


Allows:

namedQuery.Metadata.Parameters


to be used during normalization.

Parameter Handling

Kept support for:

{
  "values": {
    "Category": "Medical"
  }
}


and query-string fallback:

?Category=Medical


through common parameter extraction.

Named Query Metadata Handling

Important discussion:

When Metadata Exists

Normalize using metadata.

Example:

Category -> string
Amount -> decimal

When No Metadata Exists

Observed:

namedQuery.Metadata.Parameters.Count == 0


caused values to be dropped.

Decision:

if (parameters is null ||
    parameters.Count == 0)
{
    return values;
}


Reason:

ASP.NET Core should not decide whether parameters are allowed.
Queryable validator should decide.
Preserving values is preferable to silently deleting them.
