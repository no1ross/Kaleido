1. Core Requirements

Kaleido is a metadata-driven reference data framework

Supports filtering, searching, sorting, paging, and named queries.
Must remain data-source agnostic.
Supported sources may include:
CSV
SQLite
SQL Server
Sybase
REST APIs
Custom providers

Minimum implementation requirements

1 Record
1 Source (exactly one per Record)
0..N Named Queries

Consumer definition clarification

Framework Consumer
Developer using Kaleido.
Creates Records, Sources, Named Queries.
API Consumer
Calls a service that uses Kaleido.
Should know nothing about Kaleido internals.
Only sends/receives JSON.

Primary goal

API consumers should only care about valid JSON request/response contracts.
Framework consumers should not have to understand transport-specific concerns such as:
JsonElement
System.Text.Json
ASP.NET model binding
2. Architectural & Component Decisions
Query Contract Redesign
Removed interface-based request model

Removed:

IFilterExpression
ISearchExpression
QueryFilter
QuerySearch


Reason:

Polymorphic JSON is difficult across languages.
OpenAPI/Swagger support becomes harder.
REST clients should not need serializer-specific features.
Introduced Node / Condition / Group model

Filter model:

QueryFilterNode
├─ QueryFilterCondition
└─ QueryFilterGroup


Search model:

QuerySearchNode
├─ QuerySearchCondition
└─ QuerySearchGroup


Benefits:

Serializer-friendly.
OpenAPI-friendly.
REST-friendly.
Eliminates interface polymorphism.
Eliminates unsupported-expression scenarios.
Root query objects changed

Changed from:

QueryFilterGroup
QuerySearchGroup


to:

QueryFilterNode
QuerySearchNode


Reason:

Allow a single condition at the root.
Avoid unnecessary AND wrappers.
Public request contract becomes transport-friendly

Goal:

JSON
OpenAPI
Swagger
Postman
Java
Python
JavaScript


must all work naturally.

Compiler Changes
Compiler updated to consume nodes

Changed:

CompileFilter(IFilterExpression)
CompileSearch(ISearchExpression)


to:

CompileFilter(QueryFilterNode)
CompileSearch(QuerySearchNode)

Added defensive graph validation

Compiler now rejects:

Condition + Group


and

Neither Condition nor Group

Validator Changes
Validator updated for node model

Added validation for:

Condition only
Group only
Both = invalid
Neither = invalid

Added empty-group validation

Reject:

Filter group with zero filters
Search group with zero searches
