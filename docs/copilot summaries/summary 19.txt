1. Core Requirements

Primary Goal Remains Proving Kaleido

The sample application exists to prove that Kaleido can dramatically reduce service development effort while enabling multiple consumers to quickly understand and consume exposed data.
The focus should remain on validating framework concepts through a real application rather than building a production-quality e-commerce experience.

Queryable Has Been Largely Proven

Successfully validated:
Search
Filtering
Sorting
Paging
Search + Filter composition
Metadata-driven behavior
Search metadata changes immediately impact behavior without changing APIs or UI code.

Categories Are The Next Major Proof Point

Categories are intended to prove:
Named Queries + Queryable working together.
Multiple projections derived from the same business context.
A realistic application pattern where multiple service calls cooperate through shared UI state.

Category Counts Must Reflect Result Set

Categories must reflect:
Search criteria
Filters
Named Query selection
Sort criteria
Categories must not reflect paging.
Categories should show only categories that contain products in the current filtered result set.

Keep:

@Output()
queryRequestChanged

catalogState.productQuery

Categories Are "Dumb"

Categories should:

Display categories
Raise category selected event


They should not:

Own query logic
Own filtering logic
Understand products


The Catalog page orchestrates everything.

ProductCategory.Level

No runtime parsing

Major realization:

Current model:

QueryableRecord
    =
Query Context
+
Projection


is breaking down.

Categories exposed the problem.

New Separation

Current thinking:

Query Context
    =
Search
Filter
Sort
Named Queries

View
    =
Returned projection


Example:

CatalogQueryContext


drives:

ProductCatalogView

CategoryCatalogView

SupplierView

InventoryView

Interface Evolution

Current direction:

IRecordSource<TRecord>


returns:

IQueryable<TRecord>


where:

TRecord = Query Context


New concept:

IRecordView<TRecord, TView>


where:

TRecord = Query Context

TView
    = Returned projection


returns:

IQueryable<TView>

Product Context Becomes Shared Query Model

Current ProductCatalogRecord is evolving into:

Catalog Query Context

Search
Filter
Sort


even when a view does not display those fields.

Query Pipeline

    ↓

Apply Sort

Search

belong to the query context.

belongs to the view.

Categories and Product Queries
