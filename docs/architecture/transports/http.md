# HTTP transport boundaries (documented current behavior)

This page records the current HTTP transport's architectural constraints. The shared `Kaleido.Http` wire project has moved to `src/Transports/Http/Kaleido.Http/` and no longer depends on Platform; it owns HTTP JSON options, header names/sanitization, structured errors and the versioned route prefix. [`Kaleido.Queryable.Http`](../../../src/Capabilities/Queryable/Kaleido.Queryable.Http/README.md) now owns only Queryable request wire DTOs, CLR-to-HTTP conversion and logical routes without ASP.NET or a central Registry dependency. Generic `Kaleido.Http.Server` now owns ASP.NET endpoint filters, body binding, correlation, exception mapping and authorization without a Process, Queryable, Platform or central Registry project reference. The [`Kaleido.Queryable.Http.Server`](../../../src/Capabilities/Queryable/Kaleido.Queryable.Http.Server/README.md) adapter now maps local source/view routes and runs through TestServer with no central Registry; Process HTTP, combined Hosting HTTP and clients remain **unmigrated** under #585. Its gate does not claim those higher adapters run. The transport adapts [Process](../capabilities/process.md) and [Queryable](../capabilities/queryable.md) but does not own their runtime decisions.

`AddHttp()` does not add host-wide middleware. Kaleido's own route groups get internal endpoint filters: the exception filter first (including malformed correlation errors), then the correlation filter after the host's authentication (headers, trace tags, echo), then JSON and caller filters. The host's unrelated endpoints get no `X-Kaleido-*` headers or Kaleido error bodies. A host endpoint calling a Kaleido client without an inbound request id causes the downstream service to generate one. Hosts do not register the internal filters (#295). Avoid setting `X-Kaleido-*` headers by hand or minting a second `RequestId`: the scoped `IKaleidoCorrelationContextAccessor` carries identity and typed clients forward it automatically ([foundation](../core.md)).

The gateway HTTP client and central-registry client use timeout, circuit breaker and retries **only for safe requests** (reads and calls with an idempotency key), configured under `Kaleido:Resilience`. See the [HTTP client README](../../../src/Http/Http.Client/README.md#resilience). Endpoint names are constants/factories in `*EndpointNames` classes owned by the relevant capability or registry HTTP adapter, not shared `Kaleido.Http`; do not inline literals in `WithName()`.

Response contracts are [transport-neutral](../principles.md#transport-neutral-response-semantics): adapters decide which messages to populate. HTTP JSON omission rules must not define an empty-collection contract that behaves differently over a future gRPC transport.
