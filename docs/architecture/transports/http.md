# HTTP transport boundaries (documented current behavior)

This page records the current HTTP transport's architectural constraints. The shared `Kaleido.Http` wire project has moved to `src/Transports/Http/Kaleido.Http/` and no longer depends on Platform; it owns HTTP JSON options, header names/sanitization, structured errors and the versioned route prefix. [`Kaleido.Queryable.Http`](../../../src/Capabilities/Queryable/Kaleido.Queryable.Http/README.md) now owns only Queryable request wire DTOs, CLR-to-HTTP conversion and logical routes without ASP.NET or a central Registry dependency. Generic `Kaleido.Http.Server` now owns ASP.NET endpoint filters, body binding, correlation, exception mapping and authorization without a Process, Queryable, Platform or central Registry project reference. The [`Kaleido.Queryable.Http.Server`](../../../src/Capabilities/Queryable/Kaleido.Queryable.Http.Server/README.md) adapter now maps local source/view routes and runs through TestServer with no central Registry; `Kaleido.Process.Http` owns JSON input envelopes, versioned routes and HTTP binding data; [`Kaleido.Process.Http.Server`](../../../src/Capabilities/Process/Kaleido.Process.Http.Server/README.md) now maps local execute/step/state endpoints over generic Process and neutral Process.Server idempotency without a Registry client. Its responses reuse `ProcessResult`/`ProcessStateSnapshot`, including pinned hand-off versions, not Platform DTOs or `executeUrl`; [`Kaleido.Process.Client`](../../../src/Capabilities/Process/Kaleido.Process.Client/README.md) now owns only neutral outbound Process contracts; [`Kaleido.Process.Http.Client`](../../../src/Capabilities/Process/Kaleido.Process.Http.Client/README.md) now resolves published Process execute/state/step bindings from the participant's hydrated unfiltered Registry, uses the shared caller/credential pipeline and adds Process-only keyed POST retries (#622). [`Kaleido.Queryable.Http.Client`](../../../src/Capabilities/Queryable/Kaleido.Queryable.Http.Client/README.md) resolves declared source/view HTTP operations from the participant's unfiltered in-memory Registry and converts neutral requests to the Queryable.Http wire format. The central Registry HTTP listener and fixed-endpoint participant client have separate direct TestServer gates; the generic shared HTTP-client pipeline does not implement dynamic capability routing. The transport adapts [Process](../capabilities/process.md) and [Queryable](../capabilities/queryable.md) but does not own their runtime decisions.

[`Kaleido.Hosting.Http`](../../../src/Composed/Hosts/Kaleido.Hosting.Http/README.md) now offers a **fluent, explicit** `MapKaleido()` root: a service selects `MapProcess()` and/or `MapQueryable()`, while the dedicated authority selects `MapCentralRegistry()`. Mapping nothing registers no endpoints; shared host conventions reach only selected Kaleido route groups. The owning adapters still build the actual routes, authorization and JSON behavior. Explicit Registry participation publishes a service for cross-service discovery, but endpoint mapping never implicitly starts participation (ADR 0050).

`AddHttp()` does not add host-wide middleware. Kaleido's own route groups get internal endpoint filters: the exception filter first (including malformed correlation errors), then the correlation filter after the host's authentication (headers, trace tags, echo), then JSON and caller filters. The host's unrelated endpoints get no `X-Kaleido-*` headers or Kaleido error bodies. A host endpoint calling a Kaleido client without an inbound request id causes the downstream service to generate one. Hosts do not register the internal filters (#295). Avoid setting `X-Kaleido-*` headers by hand or minting a second `RequestId`: the scoped `IKaleidoCorrelationContextAccessor` carries identity and typed clients forward it automatically ([foundation](../core.md)).

The shared gateway HTTP-client pipeline uses timeouts/circuit breaker and retries transient **GET/HEAD** failures under `Kaleido:Resilience`; the Process client's named pipeline also retries POSTs with one stable idempotency key after transient failures or `409` with `Retry-After` while the original request is in progress. It waits for that header, honors `NoRetry`, and stops at the configured attempt limit. An ordinary `409` (including unknown outcomes), a key-reuse `422` or an in-progress `409` after the retry budget remains visible to the caller. See the [HTTP client README](../../../src/Transports/Http/Kaleido.Http.Client/README.md#resilience). Endpoint names are constants/factories in `*EndpointNames` classes owned by the relevant capability or registry HTTP adapter, not shared `Kaleido.Http`; do not inline literals in `WithName()`.

Response contracts are [transport-neutral](../principles.md#transport-neutral-response-semantics): adapters decide which messages to populate. HTTP JSON omission rules must not define an empty-collection contract that behaves differently over a future gRPC transport.
