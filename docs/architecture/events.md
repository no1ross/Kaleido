# Eventing and the outbox

[`Kaleido.Eventing`](../../src/Events/Kaleido.Eventing/README.md) currently owns generic event envelopes, classified-payload redaction, the writer, outbox store contract/default, relay, and outbox health check. This is a **shallow, temporary** lower layer above [foundation](core.md): Process and Queryable emit their own payloads into its generic writer; they keep their stable discriminators and typed event dispatchers ([ADR 0042](../decisions/0042-event-types-belong-to-capabilities.md)). A relay-only host registers `AddProcessEventDispatch()` / `AddQueryableEventDispatch()` for the event families in its shared database without registering either runtime.

`AddEventing(KaleidoEventOptions? options)` configures the **existing outbox-backed pipeline**: `Kaleido:Events` keys overlay a copy of code options, malformed typed configuration retains `invalid_options`, invalid semantic values retain `invalid_event_options`, and the relay and health check receive the same effective options. It installs an in-memory outbox default, writer, event redaction map/provider, health check and an outbox contribution to the shared store-choice check. It does not choose a publisher. A host replaces the outbox store with `AddOutboxStore<T>()` or a provider; in-memory storage must be selected explicitly by `AddInMemoryStores()` and cannot be shared across instances.

At request time Process writes `ProcessCreated` and `StepCompleted` inside the state transaction when the provider supports both stores on one database; `PlanBuilt`, `ExecutionCompleted` and `QueryExecuted` are written afterward without a transaction. A failure to enqueue these later events is logged and counted, never returned to the caller. State changes and their events commit together; a shared outbox database may contain entries from several writer services and versions. `KaleidoEventPayloadWriter` applies `IKaleidoEventRedactor`s in registration order, then the event-specific `AddEventRedaction()` policy to classified values. Without a policy classified values are erased; log redaction is independent (ADRs 0012, 0013, 0025). The outbox entry retains writer service/version and a stable JSON envelope/discriminator.

## Classified payloads

Mark sensitive properties on view/source/step types with application `DataClassificationAttribute` subclasses (`[PHI]`, `[PII]`; `[property: PHI]` for positional records). `AddEventRedaction(r => ...)` uses the standard `IRedactionBuilder` API to erase, HMAC, keep (`NullRedactor`) or supply an encrypting redactor per classification. Without an event policy classified values are erased. The host's `AddRedaction` is for **logs**, not events, so policies may differ (ADR 0025). For other transformations (information-request answers, per-view rules) register `IKaleidoEventRedactor` with `AddEventRedactor<T>()`. Event redaction occurs before the outbox write; caller responses are never redacted (ADR 0013).

`AddOutboxRelay<TPublisher>()` is an explicit publisher choice on one host per outbox database. The relay claims leased batches, publishes at least once through a timeout/circuit-breaker pipeline (no Polly retry inside a claim), retries failed entries on a durable exponential-backoff schedule and parks after the configured limit; consumers deduplicate by `EventId`. A write wakes the local relay immediately, otherwise polling backs off to 10 seconds while empty. An expired claim lets another relay instance resume after a crash; a crash between publish and removal may redeliver. Every Eventing host watches relay heartbeat and backlog in its own `kaleido-outbox` health check. A database without a relay keeps growing ([ADR 0036](../decisions/0036-stores-scoped-by-service-and-a-shared-outbox-relay.md)).

#592 separately decides Eventing's **final** level, internal ownership and whether a distinct `AddEventOutbox()` would have meaningful work. Do not infer that the current single `AddEventing()` registration or compatibility namespace override is a final design. The [consumer guide](../guide/events-and-outbox.md) covers usage and delivery guarantees.
