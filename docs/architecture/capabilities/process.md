# Process capability

[`Kaleido.Process`](../../../src/Capabilities/Process/Kaleido.Process/README.md) owns step declarations/handlers, graph validation and planning, execution, recovery, resumable `ProcessContext` (`Kaleido.Process.Context`) keyed by `ProcessKey` (`Kaleido.Process.Storage`), `IProcessContextStore`/`IProcessTransactions`, Process events and `ProcessorObservability` telemetry. Its root namespace is `Kaleido.Process`, with folder-aligned subnamespaces. A **Processor** hosts and executes steps; a **Process** is one executing instance. Step names remain unmodified type names in state, events and transport requests. `ProcessContext` is current resumable state, not historical evidence; emitted events record what happened. A valid `ServiceVersion` is required for every service; persisted `ProcessKey.ProcessorVersion` and `ProcessContext.ProcessorVersion` may remain nullable for legacy reads. No stored state is silently migrated.

`AddProcess()` explicitly scans the `IKaleidoBuilder` assemblies and registers the public scoped `IProcessorRuntime` when there are steps, with typed event dispatch and a no-op transactions fallback. Console jobs and future transport adapters submit typed `ProcessRequest` instances (usually `ProcessRequest.ForStep`) and inspect `ProcessResult`/`ProcessStepResult`; the concrete `ProcessorRuntime` and local planning registries remain internal. Hosts authorize callers before invoking this neutral runtime. It does **not** register an in-memory context or idempotency store. `AddProcessEventDispatch()` registers only typed dispatch for relay-only hosts. The later Provider owner offers explicit `AddInMemoryProviders()` for development; production registers durable stores. Process writes through [Eventing](../events.md)'s generic writer and owns stable `ProcessEventTypes` discriminators beside payloads (ADR 0042). `StepCandidateBuilder`, `StepCandidateValidator`, `StepCandidateConsistencyChecker`, `StepCandidatePlanner` and `StepCandidateNextStepChecker` prepare typed candidates; `ProcessorExecutor` executes accepted steps and retains recovery state after a failed save. Runtime registries remain local and project only published descriptors to the central Registry. A stale conditional save raises `ProcessConcurrencyException` (`Kaleido.Process.Exceptions`) with `pro_process_conflict`.

The public `ProcessStateSnapshot` projects current durable state without the store's optimistic-concurrency version or internal request ids; required/available steps remain **names** with any pending `InformationRequest`, while the `ProcessStepHandlerResult.HandOff(target, result, stepName)` overload selects an existing `ProcessStepResult` for transport-neutral hand-off continuation, without another public response view. These result/read contracts have no JSON, HTTP or callable route properties. The HTTP `ExecuteProcessRequest`/`ProcessStepRequest` and `ExecuteStepRequest<T>` input envelopes, versioned routes and Registry binding contribution belong to [`Kaleido.Process.Http`](../../../src/Capabilities/Process/Kaleido.Process.Http/README.md); Process.Http.Server later authorizes and reads JSON into typed neutral Process requests and serializes the existing generic results. A future outbound client uses the participant's hydrated unfiltered Registry bindings to call a named step ([ADR 0047](../../decisions/0047-process-response-step-identity-registry-owned-bindings.md), #619/#617/#618). Do not publish another `executeUrl` in a Process result.

`ProcessorTransition` begins, saves state, writes the transition event to the Eventing outbox and commits, or rolls back. For atomicity, `IProcessContextStore` and the outbox must share the **same provider session/transaction**, not merely the same database; this applies to any provider technology. Register `AddContextStore<T>()` and `AddTransactions<T>()` explicitly; Eventing owns the outbox. [Foundation](../core.md) provides identity and correlation but owns none of these stores.

[`Kaleido.Process.Server`](../../../src/Capabilities/Process/Kaleido.Process.Server/README.md) independently owns neutral admission and replay under `Kaleido.Process.Server.Idempotency`: `IProcessIdempotencyStore`, `IdempotencyRecord`, `IdempotencyState`, `IdempotencyReplay` (required format identifier plus opaque bytes) and `InMemoryProcessIdempotencyStore`. `AddIdempotencyStore<T>()` is an explicit Server registration, not part of `AddProcess()`. Transports choose scopes, request hashes and response encodings; the existing HTTP and SQLite adapters have **not** migrated to this API (#587), and old replay rows have not been converted. See [ADR 0044](../../decisions/0044-process-server-idempotency-ownership.md). Stable event/error/metric string values did not change with the CLR namespaces.

Consumer declarations, lookups, registration and retry expectations are in [Process authoring](process-authoring.md); the runtime-decided question/answer contract is [information requests](information-requests.md). The [Process README](../../../src/Capabilities/Process/Kaleido.Process/README.md) and scoped AGENTS rules cover implementation invariants.
