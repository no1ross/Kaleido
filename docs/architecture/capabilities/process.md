# Process capability

[`Kaleido.Process`](../../../src/Capabilities/Process/Kaleido.Process/README.md) owns step declarations/handlers, graph validation and planning, execution, recovery, resumable `ProcessorContext` keyed by `ProcessKey`, process-state/idempotency/transaction provider seams, Process events and `ProcessorObservability` telemetry. It is step-centric: a **Processor** hosts and executes steps; a **Process** is one executing instance. A step's name remains its unmodified type name in state, events and transport requests. `ProcessorContext` stores current resumable state, not historical evidence; emitted events record what happened.

`AddProcess()` explicitly scans the `IKaleidoBuilder` assemblies and registers the runtime/store defaults. `AddProcessEventDispatch()` registers only the typed dispatcher for relay-only hosts. Process writes through [Eventing](../events.md)'s generic writer and owns the stable `ProcessEventTypes` discriminators beside their payload types (ADR 0042); Eventing does not know the concrete types. `StepCandidateBuilder`, `StepCandidateValidator`, `StepCandidateConsistencyChecker`, `StepCandidatePlanner` and `StepCandidateNextStepChecker` prepare typed candidates; `ProcessorExecutor` executes accepted steps and preserves recovery state after a failed save. Runtime registries (`IProcessorStepRegistry`, `IProcessorRegistry`) remain internal and expose only a published projection to Registry. With a shared durable transaction, `ProcessorTransition` saves state and the transition event atomically. `IKaleidoContextStore`, `IKaleidoIdempotencyStore` and `IKaleidoTransactions` are independent seams, one implementation each: use `AddContextStore<T>()`, `AddIdempotencyStore<T>()`, `AddTransactions<T>()`, or the SQLite provider's corresponding registration methods for a reference durable implementation. The Eventing owner handles the outbox. [Foundation](../core.md) provides identity, correlation and the generic store-choice check without depending on Process.

This page captures the **shallow extraction** (#589), not a completed deep naming/ownership review: `Kaleido.Processor.*` public namespaces and `<RootNamespace>Kaleido</RootNamespace>` remain temporarily; the HTTP-shaped idempotency replay record is separately deferred (#587). Consumer declarations, lookups, registration examples and retry expectations are in [Process authoring patterns](process-authoring.md); the full runtime-decided question/answer contract is [information requests](information-requests.md). The full registration, relationship, paging-independent planning and recovery invariants live in the [project README](../../../src/Capabilities/Process/Kaleido.Process/README.md) and its scoped AGENTS rules until the deep Process unit replaces those with the final design.
