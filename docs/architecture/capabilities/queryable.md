# Queryable capability

[`Kaleido.Queryable`](../../../src/Capabilities/Queryable/Kaleido.Queryable/README.md) owns source/view declarations, metadata/discovery, validated query compilation, paging, local/delegated execution, Queryable events and `QueryableObservability` telemetry. The **source** is the identity; its query context describes how it is queried. A type is exactly one source or view capability; a view references a registered local source. The runtime (`QueryableService`, `QueryContextEngine`, `DelegatedQuerySourceEngine`) dispatches by queried type, with no lane order or fallback; `QueryRequestCompiler` and `QueryRequestValidator` validate consumer queries before both local and delegated execution. The internal source/view registries publish only the metadata needed by Registry. `IQueryContextExecutor<TView>` is a public provider seam: register an open-generic provider implementation with `services.AddSingleton(typeof(IQueryContextExecutor<>), typeof(MyExecutor<>))` so native `CountAsync`/`ToListAsync` replace the default async-enumeration/sync fallback.

`AddQueryable()` explicitly scans the `IKaleidoBuilder` assembly set, registers the runtime and typed Queryable event dispatch; `AddQueryableEventDispatch()` registers only the dispatcher for relay-only hosts. Queryable's event payload and stable `QueryableEventTypes` discriminator belong here (ADR 0042), while generic envelopes/writer/relay belong to [Eventing](../events.md). Queryable does not depend on Process. HTTP converts its wire request into a CLR `QueryBody` before the runtime sees it; a delegated source (`IDelegatedQuerySource<...>` with `[QuerySource]`) returns the downstream `QueryResult<T>` without changing its total or paging semantics. `QuerySourceKind` remains service-side metadata, never a published wire kind.

`QueryBody`, `QueryFilterNode`, filters/sorts and logical operators are CLR request shapes (enums and `object?` values), not HTTP JSON; the HTTP adapter converts `QueryApiBody` before execution. Pageability belongs to each source/view separately and is never inherited. A pageable local source/view needs a sortable default ordering. `TotalCount` is the number of matches, not just the size of the returned page; a partial page determines it without an extra count; a full page or empty page beyond the start may require counting. The [authoring patterns](queryable-authoring.md) give source/view and provider-executor examples. The [project README](../../../src/Capabilities/Queryable/Kaleido.Queryable/README.md) and scoped AGENTS rules carry consumer usage and modification constraints.
