# Kaleido foundation

[`Kaleido`](../../src/Core/Kaleido/README.md) is the lower, transport-free service baseline. `AddKaleido(configuration, options)` overlays the `Kaleido` configuration section over a copy of code-supplied `KaleidoServiceOptions`, validates it before adding services and returns `IKaleidoBuilder` carrying configuration, service options, the service collection and a deduplicated assembly scan set. It registers logging, a host-overridable `TimeProvider`, scoped correlation/caller accessors and shared CLR metadata/constraint projection (`TypeDescriber` creates `DataTypeDescriptor` and checks supported CLR types; `ConstraintMapper` projects `ValidationAttribute` to `ConstraintContract`). It does **not** register Process, Queryable, Eventing or a publisher.

## Options and correlation

Options are startup inputs: record types use `get; init;` and defaults; each owner overlays only named values from its configuration section onto a copy of code-supplied options ([ADR 0030](../decisions/0030-options-are-immutable-configuration-overrides-code.md)). Precedence is defaults, then code, then configuration. Invalid, blank, out-of-range or unreadable values fail startup rather than being silently replaced. A null nested positional record with a collection must supply a declared default instance (an internal parameterless constructor is sufficient) or a code value; without one the overlay rejects it rather than duplicating collection items through constructor binding (#600). Foundation owns `Kaleido`; Queryable owns `Kaleido:Queryable`; Eventing owns `Kaleido:Events`; current `Kaleido:Http`, `Kaleido:Resilience`, `Kaleido:Registry:Cache`, `Kaleido:OpenTelemetry` and `Kaleido:Mcp` sections belong to their respective (not yet migrated) owners. Their Add* calls take optional code options; defaults, code and configuration retain that precedence. `MapKaleidoHttp()` has no options; `Kaleido:Clients` is not an endpoint configuration.

The scoped `IKaleidoCorrelationContextAccessor` carries request identity; callers never mint a second `RequestId` or set `X-Kaleido-*` transport headers by hand. The [correlation flow](correlation.md) describes inbound trust, caller tags and outbound propagation; [authorization](authorization.md) is host-enforced: Core's `Kaleido.Registry` namespace owns declarations/metadata and transport-neutral `Kaleido.Server` owns mode and the service-wide default.

`ServiceName` and `ServiceVersion` are required at startup (from code or the configuration source of truth). `InstanceId` is internal and generated for each running instance; it is not JSON-bound. `Assemblies` and `TypeFilter` remain in `KaleidoServiceOptions` by owner decision; assemblies are code-only and explicit. Service authorization and Process's entry flag moved to their owners, as did Eventing's `Kaleido:Events` section. The [incremental JSONC configuration inventory](../guide/examples/kaleido-settings.jsonc) currently lists every foundation JSON setting and marks code-only inputs. `KaleidoResilienceSettings` is currently shared by the HTTP client and Eventing, and classification inspection is shared by capability metadata and event redaction; moving either up into one consumer would reverse a dependency.

Foundation registers no provider or store-choice check. Process and Eventing require explicit store registrations: [`Kaleido.Provider.InMemory`](../../src/Providers/Kaleido.Provider.InMemory/README.md) offers explicit aggregate or per-store memory choices for development/tests, while durable providers implement the same contracts. Transport-neutral Hosting checks required store-registration presence at startup and does **not** reject a chosen in-memory provider merely for its technology (ADR 0049).

The foundation has no compile-time edge to [Eventing](events.md) or the [Process](capabilities/process.md) and [Queryable](capabilities/queryable.md) capabilities. Compose those owners explicitly for now; Hosting (#597) will provide the shared transport-neutral composition entry point. See [dependencies](dependencies.md) for the current graph and #591 for eventual build-time architecture enforcement.
