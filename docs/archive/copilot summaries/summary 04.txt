1. Core Requirements
Build Kaleido.Queryable as a metadata-driven query framework focused on enterprise reference/configuration data.
Keep the framework:
Strongly typed
Provider agnostic
Minimal dependency footprint
Extension-oriented only where real extension points exist
Support a consistent query model across record types:
Filtering
Searching
Sorting
Paging
Named Queries
Avoid turning Queryable into a workflow engine, rule engine, or transport-specific framework.
Keep consumers focused on:
Defining records
Defining sources
Defining named queries
Hide framework plumbing from consumers whenever possible.
Preserve support for future execution providers (especially EF-based async execution) without adding EF dependencies to Queryable core.

Metadata vs Registration Separation
Decision

Separate metadata from runtime registration concerns.

Result

Metadata now focuses on:

RecordMetadata
FieldMetadata
NamedQueryMetadata
QueryParameterMetadata
PageableMetadata


Registration now owns runtime concerns:

SourceType
NamedQueryType
RecordType
Discovery information

Reason

Metadata was becoming polluted by runtime/discovery responsibilities.

Discovery Model
Decision

Discovery builds registrations.

Responsibilities

Discovery:

Scans assemblies
Finds records
Finds sources
Finds named queries
Builds registrations

Outcome

Metadata no longer participates in discovery logic.

Record Executor
Discussion

Questioned value of:

IRecordExecutor<T>
RecordExecutor<T>

Initial Conclusion

Looked like unnecessary abstraction because it only wrapped:

query.Count()
query.ToList()

Revised Conclusion

Executor may still be valuable.

Reason

Provides an execution boundary:

Current:

Count()
ToList()


Future:

CountAsync()
ToListAsync()


using EF Core or other providers.

Architectural Direction

Execution strategy belongs to registration metadata, not source.

Source vs Executor Separation
Decision

Do NOT merge source and executor concepts.

Rejected:

IRecordSource<TRecord, TExecutor>

Reason

Source responsibility:

Create IQueryable<T>


Executor responsibility:

Materialize IQueryable<T>


Keeping them independent preserves clean separation of concerns.

Query Parameter Validation
Decision

Named query parameters are strongly typed.

Example

If metadata defines:

Amount = Decimal


then:

["Amount"] = decimal


is valid.

["Amount"] = decimal.ToString()


is invalid.

Result

Functional tests updated to use actual types.
