1. Core Requirements
Product Catalog & Categories

Product catalog must support:

Search
Filtering
Sorting
Paging
Category navigation

Category navigation must:

Always remain synchronized with the current product result set
Respect search/filter/sort criteria
Ignore paging
Display counts based on the full matching result set
Show only categories represented by the current result set

Products may belong to multiple categories.

Category navigation is intended to be:

A browse/navigation mechanism
Not merely a list of assigned categories

Category counts should represent:

Matching products
Not paged products
Shopping Cart

Shopping cart validation goal:

Prove Process can write state
Prove Queryable can independently read state

Shopping cart UI should:

Never depend on process responses containing updated state
Refresh itself through Queryable projections

Current proof point:

Add-to-cart updates persisted state
ShoppingCartSummaryView reflects updated state
Cart badge updates correctly

Confirmed Design Direction

QueryContext represents:

Searchable/filterable universe
Raw source data

QueryViews represent:

Consumer-specific projections
Aggregations
Transformations
Alternative representations
Proven Examples

        ↓

ProductCatalogView

CategoryCatalogView


and

ShoppingCartQueryContext
        ↓

ShoppingCartSummaryView

ShoppingCartDetailView

Category Hierarchy Architecture
Original Issue

Category view was returning only:

Laptops
Mice
Headsets


because products were assigned only to leaf categories.

Final Solution
Use:
CategoryPath


to build hierarchy.

Roll counts upward.

Example:

Electronics/Computers/Laptops


expands to:

Electronics
Electronics/Computers
Electronics/Computers/Laptops


with aggregated counts.

Important Result

Category hierarchy now derives entirely from:

Current product result set


and remains synchronized automatically.

Category View Responsibilities

Moved from:

Product query source


to:

CategoryCatalogView


Responsibilities:

Join category assignment tables
Build hierarchy
Perform category rollup logic

This validated that QueryViews can:

Join additional tables
Transform data substantially
Not merely perform projections
