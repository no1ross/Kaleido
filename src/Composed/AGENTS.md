# Composition area rules

Inherit root and `src/` guidance. A composed host calls each owner registration with its own validated options; `AddKaleido()` remains foundation-only. Transport-neutral `Kaleido.Hosting` must work for a console job or relay host as well as future HTTP hosting. Its consumer-owned job can resolve the public `IProcessorRuntime` and `IQueryableService` without friend access; Hosting itself chooses no work. Hosting must not depend on ASP.NET, a nonexistent gRPC implementation or a mandatory central Registry client. The Hosting provider check examines final DI registrations and reports missing required Process/Eventing stores; any registered implementation, including explicitly chosen in-memory, is valid. Do not introduce hidden provider selection, reverse project references or duplicate capability/authorization policy. `Kaleido.Hosting.Http` exposes only explicit fluent HTTP endpoint mapping over the owning Process, Queryable and central Registry adapters; its `MapKaleido()` root maps nothing, chooses no Registry participant and applies host conventions only to selected routes (ADR 0050). Consult [dependency boundaries](../../docs/architecture/dependencies.md), the owner README/AGENTS files and affected integration fixtures when composition is implemented; no fake no-op `AddGrpcHosting()`.
