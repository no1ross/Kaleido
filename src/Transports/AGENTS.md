# Transport-neutral Server and Client rules

Inherit root and `src/` guidance. This area will contain transport-neutral Server and Client owners; their shared options, caller/authorization handoff, registry participation and transport selection must not depend on ASP.NET, HTTP or gRPC implementation details. A transport adapts existing capability contracts and caller identity: it must not reimplement Process/Queryable decisions or make Core depend upward. The existing `src/Server/` and `src/Client/` projects remain outside this area until their own migrations; the current non-packable `Kaleido.Server.Next` shell only binds authorization mode and service defaults. Resolve its temporary `.Next` assembly/root-namespace bridge when Server is processed, with namespaces following the final project and directories.

Transport-specific wire, endpoint and client behavior belongs under the [HTTP](Http/AGENTS.md) or [gRPC](Grpc/AGENTS.md) child scope when those projects move. Do not introduce fake no-op transport registrations. Read [authorization](../../docs/architecture/authorization.md) and [dependencies](../../docs/architecture/dependencies.md) before changing a shared seam.
