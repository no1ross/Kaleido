# Transport-neutral Server and Client rules

Inherit root and `src/` guidance. This area will contain transport-neutral Server and Client owners; their shared options, caller/authorization handoff, registry participation and transport selection must not depend on ASP.NET, HTTP or gRPC implementation details. A transport adapts existing capability contracts and caller identity: it must not reimplement Process/Queryable decisions or make Core depend upward. `Kaleido.Server` now owns only transport-neutral authorization mode, the service default and `AddServer()`; its old ASP.NET files were relocated to the existing HTTP-server owner for their later gate. The retired mixed `src/Client/` package must not be reintroduced; neutral client contracts belong to their capabilities. Neither neutral Server nor generic HTTP Server requires the central Registry to map or execute local capabilities; optional Registry client/publication behavior belongs to that separate integration. Namespaces follow the final project and directories, with no `.Next` bridge.

Transport-specific wire, endpoint and client behavior belongs under the [HTTP](Http/AGENTS.md) child scope today; future gRPC projects should define their own scope when implemented. Do not introduce fake no-op transport registrations. Read [authorization](../../docs/architecture/authorization.md) and [dependencies](../../docs/architecture/dependencies.md) before changing a shared seam.
