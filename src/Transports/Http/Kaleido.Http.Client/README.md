# Kaleido.Http.Client

This is the shared **outbound HTTP-client pipeline** for Registry, Process and Queryable adapters. It is lower than those adapters and depends on the foundation and shared [`Kaleido.Http`](../Kaleido.Http/README.md) wire only—not Platform, the central Registry authority, ASP.NET, or a particular capability. `IHttpClientFactory` is the existing factory: each adapter registers a named gateway client, then builds its own fixed Registry request or dynamically resolved capability request. There is no new generic client factory or request hierarchy here.

## Resilience

The shared named-client pipeline bounds a whole call and each attempt, retries transient failures only on GET/HEAD, and uses a circuit breaker. Configure its `Kaleido:Resilience` options on the gateway; Process-specific idempotent execution retry stays with Process's outbound adapter.

## What a call carries: the caller's token, or the service's own (#574)

A per-request HTTP extension stamps the Core correlation context's end-to-end request ID, origin, origin tool and process ID before an adapter sends its request. It sanitizes header values and never forwards inbound per-hop calling-processor/step tags. When an adapter calls from inside its own executing step, the shared stamper uses that host's service name and current step for the per-hop tags, whether the outbound operation is Process, Queryable or Registry. It reads the adapter's scoped context at send time, rather than capturing a scoped accessor in a pooled `IHttpClientFactory` handler. For a front door such as MCP whose process id arrives as a tool argument rather than an inbound header, the internal `IKaleidoProcessForwarding.ForwardProcess(processId)` scope overrides only the outbound `X-Kaleido-Process-Id`: an explicit id passed to a Process **execution** method wins, then that async-flow scope, then Core's inbound correlation context. A Process state GET instead preserves the call's ambient correlation, which need not equal the resource id being read. Queryable, Process and Registry adapters all use the shared stamper; the scope restores its previous value when disposed and does not alter credentials, request id or origin headers. Local-only hosts do not install a forwarding scope.

`AddKaleidoHttpClientPipeline(options?)` binds `KaleidoClientOptions` (`Kaleido:BaseUrl`, `Kaleido:Resilience`, `Kaleido:OnBehalfOfCalls`) with configuration overriding code, validates the gateway address, refuses obsolete per-service `Kaleido:Clients` entries, and registers the shared filter. At host startup the pipeline warns if a non-loopback gateway uses HTTP, without logging URL credentials. Enrolled named clients log method, remote service and path at Debug and non-success HTTP status at Warning; a normal conditional `304` is not a warning. The logging handler omits query strings, Authorization and idempotency keys. A named client is enrolled explicitly through the package's internal registration seam; other host `HttpClient`s are untouched. The shared registration checks service-name keys for capability clients, but the Process and Queryable adapters each register their own scoped `[FromKeyedServices("service-name")]` client alongside the service/version factory; this layer does not select Registry routes. `AddKaleidoClientHandler<THandler>()` adds a host-owned credential handler to enrolled clients in registration order. The innermost `KaleidoOnBehalfOfGuard` enforces the final token policy after those handlers. A host's handler reads `KaleidoCallContext.Of(request)` to learn whether the request is the service's own or is on behalf of its authenticated caller. Never log `CallerAuthorization` or copy a caller token into a service-own request.

- **`ServiceOwn`**: shared Registry refresh, registration and heartbeat use whatever app-only credential the host handler supplies.
- **`OnBehalfOfCaller`**: caller-filtered discovery or a later capability call uses the caller's credential under explicit `Forward` (same audience) or a host-provided exchanged credential under `Exchange`. Exchange refuses an absent/unchanged inbound token before sending; MCP hosts require it. Anonymous caller requests carry no authorization.

The shared resilience pipeline bounds attempts and retries transient failures on GET/HEAD; it does not contain Process's `Idempotency-Key` or `409 Retry-After` execution policy. The [`Kaleido.Process.Http.Client`](../../../Capabilities/Process/Kaleido.Process.Http.Client/README.md) named client retries transient keyed POST failures and in-progress `409` with `Retry-After` using the original key and a bounded delay; ordinary `409`, key-reuse `422` and unknown outcomes still reach the caller. `KaleidoHttpClientException` and its stable error codes retain service errors across HTTP failures; Registry-specific failures use `KaleidoRegistryClientException` in [`Kaleido.Registry.Client`](../../../Capabilities/Registry/Kaleido.Registry.Client/README.md).

`Kaleido.Registry.Http.Client` owns the known `/registry` endpoints, conditional ETags and Registry participation. Queryable's service-name factory and published-route resolution now live in [`Kaleido.Queryable.Http.Client`](../../../Capabilities/Queryable/Kaleido.Queryable.Http.Client/README.md); The Process outbound adapter now lives in [`Kaleido.Process.Http.Client`](../../../Capabilities/Process/Kaleido.Process.Http.Client/README.md), with Registry selection outside this shared pipeline and local caller-per-hop headers stamped consistently by the shared helper. Neither capability's routing belongs in this shared pipeline. Local-only services never need this pipeline.
