# HTTP transport rules

Inherit root, `src/` and `src/Transports/` guidance. `Kaleido.Http` now lives here and owns shared HTTP JSON, headers, structured errors and versioned route-prefix mechanics, **without** a Platform, capability, central Registry or ASP.NET reference. Process/Queryable/Registry URLs and requests belong to their own `.Http` projects. `Kaleido.Http.Server` owns generic ASP.NET filters, correlation, authorization and body binding without Platform, capability or central Registry project references. Its filters apply only to Kaleido route groups, never host-wide JSON/auth/error behavior. `Kaleido.Http.Client` now owns only the lower shared named-client, credential-handler/guard, gateway options and safe-read resilience seam: do not move Process/Queryable dynamic routing or Process idempotency into it. Capability-specific client source still parked under `src/Http/` awaits its own #585 unit. Read [HTTP boundaries](../../../docs/architecture/transports/http.md) and affected READMEs before changing the seam; move matching fixtures and update docs with each owner. Neutral Server must not implement HTTP behavior.
