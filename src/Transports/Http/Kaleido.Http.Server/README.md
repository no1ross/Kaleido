# Kaleido.Http.Server

This project owns **generic ASP.NET Core HTTP server mechanics**: JSON body binding, endpoint-scoped error/JSON/caller/correlation filters, ASP.NET authorization and correlation trust. It does not map a Process, Queryable or central Registry endpoint. Those routes and their options belong to capability-specific adapters, Registry HTTP and composed Hosting HTTP; the higher adapters are still being migrated under #585.

The project references only neutral [`Kaleido.Server`](../../Kaleido.Server/README.md) and shared [`Kaleido.Http`](../Kaleido.Http/README.md), with foundation transitively available through Server. In particular it has no Platform, Process, Queryable or central Registry project reference. `Kaleido.Registry.AuthorizationMetadata` is a shared authorization declaration in the **Core** package, not a dependency on the central Registry project.

## Registration

`AddHttp()` on an `IKaleidoBuilder` registers ASP.NET routing, `IHttpContextAccessor`, authorization, the scoped Kaleido authorizer and the exception handler. It binds `KaleidoHttpServerOptions` under `Kaleido:Http`. `TrustCorrelationIdentity` is code-only: when omitted, identity-bearing correlation headers are trusted only without an authentication scheme or for an authenticated caller. A second `AddHttp()` call fails with `duplicate_registration`. Transport-neutral authorization mode and service default come from `AddServer()`.

Neither call adds host-wide middleware, endpoint routes, a Process execution service, a Registry client, a provider or an authentication scheme. The host supplies authentication and its normal ASP.NET middleware. Higher adapters apply these internal filters only to their Kaleido route groups, in this order: exception, correlation, JSON and caller. Unrelated host endpoints keep their own JSON, authorization and exception behavior.

The exception handler maps Core validation and malformed requests to 400, authorization to the host's challenge/forbid behavior, configuration/framework errors to a redacted 500, and unexpected failures to a redacted 500. It logs client disconnects without writing another response. Process conflict, recovery, idempotency and response-message behavior belongs to Process HTTP and is **not** mapped here.

`KaleidoJsonBody<T>` binds malformed JSON inside Kaleido endpoint handling so it receives a structured 400 from the exception filter. When an adapter declares an `application/json` request schema with ASP.NET's `Accepts` metadata, routing rejects a different content type with its standard empty 415 **before** Kaleido's endpoint filters run. `KaleidoJsonEndpointFilter` serializes the route's responses with [`KaleidoJsonOptions`](../Kaleido.Http/README.md). Correlation reads and sanitizes shared HTTP headers, initializes the scoped context, tags the current trace and echoes the correlation headers on Kaleido responses.

See [HTTP transport boundaries](../../../../docs/architecture/transports/http.md), [authorization](../../../../docs/architecture/authorization.md) and [correlation](../../../../docs/architecture/correlation.md). [Process HTTP](../../../Capabilities/Process/Kaleido.Process.Http.Server/README.md) and [Queryable HTTP](../../../Capabilities/Queryable/Kaleido.Queryable.Http.Server/README.md) adapters map their own local capability routes through these shared filters without imposing Registry participation on this project.
