# Kaleido.Process.Client

Transport-neutral outbound Process contracts: `IKaleidoProcessorClient` and `IKaleidoProcessorClientFactory`. This contracts-only assembly references generic [`Kaleido.Process`](../Kaleido.Process/README.md); it has no Registry authority/client, HTTP, ASP.NET, Platform, JSON or network implementation and never starts Registry participation. Local `AddProcess()` works without this project.

The client sends a typed neutral `ProcessRequest` with one or more named steps, or a typed/by-published-name single step, and reads the existing `ProcessResult`. `GetProcessStateAsync()` reads `ProcessStateSnapshot?` (null means the process was not found). A remote service's CLR step need not be referenced: a local mirror record with the same published type name supplies a typed single-step input, or a caller submits a name and object at runtime. No client call returns an old HTTP-specific step-response wrapper or introduces another public step-outcome view. A logical idempotency key is a neutral optional argument; the chosen adapter handles its transport representation and retries without reusing a new key for the same logical call.

`GetClient(serviceName)` selects the currently published service version when starting. For continuation, especially after a hand-off, use `GetClient(targetProcessorName, targetProcessorVersion)` from `ProcessResult` or `ProcessStateSnapshot`: pinning this version is necessary because a later Registry current version may not own the process. The separate [`Kaleido.Process.Http.Client`](../Kaleido.Process.Http.Client/README.md) resolves operations from the participant's already-hydrated **unfiltered** Registry and adapts inputs at the HTTP boundary; this project never chooses a route or serializes JSON (#621, #622, ADR 0040/0047).
