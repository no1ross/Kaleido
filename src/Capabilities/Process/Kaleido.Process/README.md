# Kaleido.Process

The generic Process capability owns step and handler declarations, discovery, planning, execution, resumable state, recovery, Process events and runtime telemetry. Its namespaces follow `Kaleido.Process` and project-relative folders (`Context`, `Execution`, `Storage`, `Exceptions`, and so on). It depends on the transport-free [`Kaleido` foundation](../../../Core/Kaleido/README.md) and [`Kaleido.Eventing`](../../../Events/Kaleido.Eventing/README.md)'s generic writer/outbox seams (Eventing's placement is under #592). Process does not own Queryable, the central registry, transport parsing or a persistence technology.

Call `AddKaleido(configuration, options).AddEventing().AddProcess()` with explicit assemblies and choose stores separately. `AddProcess()` scans and validates the steps and handlers, registers the runtime, typed event dispatch and a no-op `IProcessTransactions` fallback when steps exist; it **does not** register an in-memory context or idempotency store. `AddContextStore<T>()` and `AddTransactions<T>()` select Process-owned state and transaction implementations. The later `Kaleido.Provider` owner explicitly offers `AddInMemoryProviders()` for development; Eventing owns outbox registration. `AddProcessEventDispatch()` registers typed Process event delivery independently for relay-only hosts.

`IProcessStep`, `[ProcessStep]`, `IProcessStepHandler<TStep>` and `ProcessStepHandlerResult` are the consumer declaration/result contracts. `ProcessContext` (`Kaleido.Process.Context`) is current resumable state, not an audit log; the event stream records what happened. State is keyed by `ProcessKey` (`Kaleido.Process.Storage`), and a stale conditional save raises `ProcessConcurrencyException` (`Kaleido.Process.Exceptions`, `pro_process_conflict`). A service must supply `ServiceVersion` from code or configuration; `ProcessKey.ProcessorVersion` and persisted `ProcessContext.ProcessorVersion` remain nullable to read legacy state, which this change does not migrate.

## Execution and boundaries

Process is step-centric: declare an `IProcessStep` type with `[ProcessStep]` metadata and exactly one handler, then register its assembly with `AddProcess()`. The public step name remains unmodified `Type.Name` in state, events and requests. Handlers name the next step by type; names are produced at the boundary. `StepCandidateBuilder`, `StepCandidateValidator`, `StepCandidateConsistencyChecker`, `StepCandidatePlanner` and `StepCandidateNextStepChecker` prepare the plan before `ProcessorExecutor` invokes handlers. `ProcessorTransition` begins a transaction, saves state, adds its transition event to the outbox and commits (or rolls back). Atomicity requires **both** stores to join the same provider session/transaction; sharing a database alone does not suffice, whatever the provider technology. Recovery holds an outcome whose save failed after its handler ran.

`ProcessEventTypes` declares stable Process event discriminators beside event payload types. Eventing provides the generic envelope/outbox/relay, not a catalog of Process events. Runtime registries are Process-local and publish a projection; they do not implement the central registry. Preserve existing event, error-code and telemetry string values across namespace changes.

Idempotency admission is **not** a generic Process runtime store: [`Kaleido.Process.Server`](../Kaleido.Process.Server/README.md) owns the neutral `Kaleido.Process.Server.Idempotency` contracts, including `IProcessIdempotencyStore`, `IdempotencyRecord`, `IdempotencyState`, `IdempotencyReplay` and `InMemoryProcessIdempotencyStore`. Replay has a format identifier and opaque bytes, not an HTTP status or JSON body. The HTTP and SQLite adapters remain unmigrated (#587); do not assume their previous contracts interoperate with the new Server contract or that persisted replay rows are migrated.
