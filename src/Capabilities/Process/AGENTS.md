# Process modification rules

Inherit root, `src/` and `src/Capabilities/` guidance. Read [Process architecture](../../../docs/architecture/capabilities/process.md), [authoring contracts](../../../docs/architecture/capabilities/process-authoring.md), [information requests](../../../docs/architecture/capabilities/information-requests.md) and the [package README](Kaleido.Process/README.md).

- Process is step-centric, not Queryable. `IProcessStep` identifies a step; `[ProcessStep]` describes it with nonempty display/description; its public name is unmodified `Type.Name`, unique across the scan. Exactly one handler per discovered step. Reject self/circular/missing `DependsOn`/`AvailableAfter` relationships at startup (`pro_invalid_registration`); `AvailableUntil` closes a step, not part of the dependency graph.
- Keep planning stages distinct: resolve/hydrate (`StepCandidateBuilder`), DataAnnotations (`StepCandidateValidator`), history/consistency (`StepCandidateConsistencyChecker`), ordering (`StepCandidatePlanner`), next-step and pending-answer admission (`StepCandidateNextStepChecker`), and state/event persistence (`ProcessorExecutor`). The next step remains typed internally; serialize its name only at a boundary.
- Runtime registries (`IProcessorStepRegistry`, `ProcessStepRegistration`) and in-process entry points (`IProcessorRuntime`, `ProcessRequest`/`ProcessorRequest`/`ProcessResult`) remain internal; only adapters in this repository invoke them (#297).
- `ProcessorContext` is current resumable state, not event history. A pending `RequiredInformationRequest` lives in that state; the implementer owns question content and historical audit. Save transitions and their Process events atomically when the chosen transaction covers both stores; do not move Process event payloads or `ProcessEventTypes` into Eventing. Process must not parse HTTP input or depend on JSON as a transport convenience (#591).
- The current `Kaleido.Processor.*` namespace/RootNamespace override and HTTP-shaped idempotency replay fields remain transitional (#589/#587). Keep matching tests in `Kaleido.Process.UnitTests` and run active source/test gates plus directly affected Eventing tests for writer/dispatch changes.
