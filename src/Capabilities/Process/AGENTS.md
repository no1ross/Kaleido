# Process modification rules

Inherit root, `src/` and `src/Capabilities/` guidance. Read [Process architecture](../../../docs/architecture/capabilities/process.md), [authoring contracts](../../../docs/architecture/capabilities/process-authoring.md), [information requests](../../../docs/architecture/capabilities/information-requests.md), the [Process README](Kaleido.Process/README.md) and [Process.Server README](Kaleido.Process.Server/README.md).

- Process is step-centric, not Queryable. `IProcessStep` identifies a step; `[ProcessStep]` describes it with nonempty display/description; its public name is unmodified `Type.Name`, unique across the scan. Exactly one handler per discovered step. Reject self/circular/missing `DependsOn`/`AvailableAfter` relationships at startup (`pro_invalid_registration`); `AvailableUntil` closes a step, not part of the dependency graph.
- Keep planning stages distinct: resolve/hydrate (`StepCandidateBuilder`), DataAnnotations (`StepCandidateValidator`), history/consistency (`StepCandidateConsistencyChecker`), ordering (`StepCandidatePlanner`), next-step and pending-answer admission (`StepCandidateNextStepChecker`), and state/event persistence (`ProcessorExecutor`). The next step remains typed internally; serialize its name only at a boundary.
- Runtime registries (`IProcessorStepRegistry`, `ProcessStepRegistration`), the concrete `ProcessorRuntime` and planners remain internal. The public neutral invocation contract is `IProcessorRuntime` with `ProcessRequest`/`ProcessorRequest`/`ProcessResult`/`ProcessStepResult`: console jobs and transport adapters use it without friend access. Hosts must authorize a step before submission; no HTTP or central Registry client is needed to execute locally. Namespaces follow `Kaleido.Process` and matching project-relative folders; keep `Processor*` for the step-hosting runtime and `Process*` for an instance.
- `ProcessContext` is current resumable state, not event history. A pending `RequiredInformationRequest` lives in that state; the implementer owns question content and historical audit. New services require `ServiceVersion`, but persisted `ProcessKey.ProcessorVersion` / `ProcessContext.ProcessorVersion` stay nullable for legacy reads; never silently rewrite records.
- `IProcessContextStore` and `IProcessTransactions` belong to generic Process; `AddProcess()` does not select in-memory stores. Save transitions and Process events atomically only when state and Eventing outbox stores participate in the **same provider session/transaction** (not merely the same database). Do not move Process event payloads or `ProcessEventTypes` into Eventing or change stable event/error/metric strings. Process must not parse HTTP input or depend on JSON as a transport convenience (#591).
- `Kaleido.Process.Server.Idempotency` owns neutral `IProcessIdempotencyStore`, admission/lease/fencing and opaque `IdempotencyReplay` bytes with a format identifier (ADR 0044). Do not put HTTP status, JSON responses or idempotency contracts back into generic Process. `AddIdempotencyStore<T>()` is explicit; `AddInMemoryProviders()` is a later Provider choice. HTTP/SQLite adapters remain unmigrated and #587 stays open; never claim compatibility or migrated replay rows. Keep matching tests in the Process and Process.Server test projects and run only active/lower-area gates.
