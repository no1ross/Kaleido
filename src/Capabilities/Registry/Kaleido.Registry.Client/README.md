# Kaleido.Registry.Client

This package owns the **transport-neutral participant** of the central Registry. A host explicitly opts in with `AddRegistryClient()` (normally via an installed Registry transport's participation method); local `AddProcess()` or `AddQueryable()` alone never registers remotely. It depends only on lower [`Kaleido.Registry`](../Kaleido.Registry/README.md) contracts and foundation facilities, not on the authority Server, ASP.NET, Process or Queryable runtimes.

At startup the participant combines the installed capability owners' local published Registry items and applies **only installed transport binding contributors**. The current participant registers only when a capability has an installed callable HTTP operation; a consumer-only host hydrates without advertising an empty service. A future gRPC adapter must extend that check for its own bindings. The service's `BuildVersion` is read once from its own entry assembly's Product/AssemblyInformationalVersion before `+commit`, never from Kaleido.dll. A publication is scoped by service name, state/route `ServiceVersion` and build version; instance identity comes from foundation.

The registrar retries registration, follows the authority's lease interval for local-health heartbeats, re-registers when the instance is unknown and deregisters best effort. The sync keeps a last-good Registry copy: it polls small availability at the authority's pace, reads capabilities when `CapabilitiesRevision` changes and uses conditional read tokens. Readiness requires an initial read and, for a publisher, a successful registration; a later transient failure does not undo readiness. Transport selection resolves a published service/version route from that hydrated **unfiltered** copy, not from a per-service address list. A caller-filtered view is for discovery, not routing. [`Kaleido.Queryable.Http.Client`](../../Queryable/Kaleido.Queryable.Http.Client/README.md) now uses the internal target resolver to select each published source/view HTTP binding from this already-hydrated copy; it performs no per-query central Registry read.

`IKaleidoRegistryClient` is the neutral typed call contract. [`Kaleido.Registry.Http.Client`](../Kaleido.Registry.Http.Client/README.md) supplies fixed HTTP endpoint calls through the shared gateway-client pipeline; a future gRPC adapter can supply the same contract without changing this participant lifecycle. Local-only hosts need neither package in their DI graph.
