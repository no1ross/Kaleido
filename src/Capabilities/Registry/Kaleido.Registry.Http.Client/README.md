# Kaleido.Registry.Http.Client

The fixed-endpoint Registry HTTP adapter implements `IKaleidoRegistryClient` from [`Kaleido.Registry.Client`](../Kaleido.Registry.Client/README.md). It depends on the lower [`Kaleido.Registry.Http`](../Kaleido.Registry.Http/README.md) route contract and shared [`Kaleido.Http.Client`](../../../Transports/Http/Kaleido.Http.Client/README.md) named-client/credential pipeline; it has **no** Registry.Server or ASP.NET reference. It never discovers the Registry in another Registry or resolves a Process/Queryable target.

## Taking part in the control Registry

`AddRegistryHttpClient(options?)` registers only the named `kaleido-registry` HTTP client and its typed fixed-endpoint calls—no hosted lifecycle or network work until invoked. `AddRegistryHttpParticipation(options?)` explicitly composes that adapter with neutral `AddRegistryClient()`: an installed Process/Queryable capability contributes its own Registry description, an installed HTTP binding contributor adds only its callable operation paths, and the participant registers only when one is callable. A reader-only participant hydrates without publishing an empty service; local-only hosts need not opt in.

`Kaleido:BaseUrl` is the one gateway address, validated by the shared client options and never a per-service map. Registration carries `ServiceName`, the route/state `ServiceVersion`, the deployed service application's Product `BuildVersion` and the foundation's instance ID. The adapter calls known `/registry` paths for registration, heartbeat, deregistration and Registry/capability/availability reads. It stamps scoped end-to-end correlation headers on each outbound request through the shared HTTP-client helper, without forwarding inbound per-hop calling-step tags. It sends and retains the authority's **weak ETags**, treating `304` as unchanged; neutral hydration decides whether a new capabilities version requires a full fetch. Registry writes and shared hydration use `KaleidoCallPurpose.ServiceOwn`; `GET /registry` inside an inbound request is marked `OnBehalfOfCaller` for the host's credential handler and the shared forwarding/exchange guard. The adapter never logs inbound credentials or silently uses an app token to discover for a caller.

A direct TestServer suite exercises the authority without an auto participant first; this client's unit/protocol functional suites cover fixed paths, typed payloads, service JWTs, ETags and reader-only hydration. Cross-project hosted publication and a real inbound JWT → async Queryable source → exchanged Registry HTTP read live in the focused Registry integration suite; no internal caller-context test seam is needed.
