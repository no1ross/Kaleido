# Kaleido.Registry.Server

This package is the transport-neutral **central Registry authority**, above the lower [`Kaleido.Registry`](../Kaleido.Registry/README.md) contracts. It owns registration validation, trusted registrant scope, instance leases and health, the rolling-deployment intersection of live builds, completeness/readiness, housekeeping, the Registry store interface, HybridCache and opaque snapshot versions. It never calls a participant and has no ASP.NET/gRPC or participant-client dependency.

## A Registry host

A host calls `AddKaleido(...).AddServer(...).AddControlRegistry(options?)` and **explicitly chooses** `AddRegistryStore<T>()` or `AddInMemoryRegistryStore()` before mapping a transport listener. In-memory storage holds Registry model objects, is lost on restart and is not shared among nodes. `IKaleidoRegistryStore` accepts/returns typed `KaleidoRegistry` models: a provider decides its own persistence encoding. Registrations are keyed by service name, route/state `ServiceVersion` and the service application's `BuildVersion`; every running instance has its own `InstanceId`. `Kaleido.Provider.SQLite` supplies a durable typed Registry store through explicit `AddSqliteRegistryProvider(connectionString)`; Registry.Server still chooses no provider. An HTTP TestServer restart scenario verifies stored registrations survive, stale instances show `Unknown` after every authority node was down, and a heartbeat restores availability. There is no released Registry SQLite data to migrate.

The authority's short-lived merged view and immutable build publications are cached separately. It assigns opaque capability, status, availability and combined snapshot versions by comparing the relevant build identities and instance/status state; unchanged views retain their versions after a cache rebuild. A semantic version may ignore heartbeat timestamps or `GeneratedAt`, so HTTP presents it as a **weak ETag**. A different Registry node can issue a different opaque token after a separate rebuild: this can cause a harmless extra `200`, not an incorrect `304`. Caller-filtered views cannot reuse the unfiltered version. The HTTP listener and its caller-specific filtering live in [`Kaleido.Registry.Http.Server`](../Kaleido.Registry.Http.Server/README.md).

## Cache (`Kaleido:Registry:Cache`)

`KaleidoRegistryCacheOptions` separates the short merged-view lifetime (`ViewTtl`, default one second) from immutable per-build capability entries (`CapabilitiesTtl`, default one year). An optional distributed HybridCache tier shares cached views; the Registry store remains authoritative on a miss or cache failure. Successful registration and removal invalidate the local merged view and advance its cache-key generation: a view build that began before the write cannot refill the new key. Routine heartbeats use the short view TTL instead of invalidating the cache on every lease renewal. An expired or invalidated view is rebuilt from the store and retains its semantic snapshot version when its relevant build/status state is unchanged. Fake-clock HTTP TestServers verify that the view rebuilds at `ViewTtl` without rereading an immutable build before `CapabilitiesTtl`, refetches after that TTL, and recovers after a failed capability read. Two authority nodes with aligned view-key generations sharing a distributed tier can reuse a built view even when the second store cannot read; an unreachable distributed tier does not prevent a store-backed read or later rebuild.

For deployment, a durable store and service/application authorization policies are required. Configure `Kaleido:Registry:RegistrantPolicy` and `ReaderPolicy` unless the host deliberately uses development-only `AuthorizationMode.None`. The host gateway owns destinations; Registry transport routes are relative logical paths only.
