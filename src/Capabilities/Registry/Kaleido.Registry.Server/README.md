# Kaleido.Registry.Server

This package is the transport-neutral **central Registry authority**, above the lower [`Kaleido.Registry`](../Kaleido.Registry/README.md) contracts. It owns registration validation, trusted registrant scope, instance leases and health, the rolling-deployment intersection of live builds, completeness/readiness, housekeeping, the Registry store interface, HybridCache and opaque snapshot versions. It never calls a participant and has no ASP.NET/gRPC or participant-client dependency.

## A Registry host

A host calls `AddKaleido(...).AddServer(...).AddControlRegistry(options?)` and **explicitly chooses** `AddRegistryStore<T>()` or `AddInMemoryRegistryStore()` before mapping a transport listener. In-memory storage holds Registry model objects, is lost on restart and is not shared among nodes. `IKaleidoRegistryStore` accepts/returns typed `KaleidoRegistry` models: a provider decides its own persistence encoding. Registrations are keyed by service name, route/state `ServiceVersion` and the service application's `BuildVersion`; every running instance has its own `InstanceId`. The SQLite provider is still unprocessed and uses the earlier unshipped JSON/hash store API; it is not part of this in-memory Registry checkpoint. Its future implementation must adopt the typed store contract before it can be offered as a durable option. There is no released Registry SQLite data to migrate.

The authority's short-lived merged view and immutable build publications are cached separately. It assigns opaque capability, status, availability and combined snapshot versions by comparing the relevant build identities and instance/status state; unchanged views retain their versions after a cache rebuild. A semantic version may ignore heartbeat timestamps or `GeneratedAt`, so HTTP presents it as a **weak ETag**. A different Registry node can issue a different opaque token after a separate rebuild: this can cause a harmless extra `200`, not an incorrect `304`. Caller-filtered views cannot reuse the unfiltered version. The HTTP listener and its caller-specific filtering live in [`Kaleido.Registry.Http.Server`](../Kaleido.Registry.Http.Server/README.md).

## Cache (`Kaleido:Registry:Cache`)

`KaleidoRegistryCacheOptions` separates the short merged-view lifetime (`ViewTtl`, default one second) from immutable per-build capability entries (`CapabilitiesTtl`, default one year). An optional distributed HybridCache tier shares cached views; the Registry store remains authoritative on a miss or cache failure. Successful registration and removal invalidate the local merged view and advance its cache-key generation: a view build that began before the write cannot refill the new key. Routine heartbeats use the short view TTL instead of invalidating the cache on every lease renewal. An expired or invalidated view is rebuilt from the store and retains its semantic snapshot version when its relevant build/status state is unchanged.

For deployment, a durable store and service/application authorization policies are required. Configure `Kaleido:Registry:RegistrantPolicy` and `ReaderPolicy` unless the host deliberately uses development-only `AuthorizationMode.None`. The host gateway owns destinations; Registry transport routes are relative logical paths only.
