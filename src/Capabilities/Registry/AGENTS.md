# Registry capability rules

Inherit root, `src/` and `src/Capabilities/` guidance. Shared authorization declarations still live in Core's `Registry/` namespace. The processed [dependency graph](../../../docs/architecture/dependencies.md) is one-way: `Kaleido.Registry` owns Core-only portable Process/Queryable item, binding and read contracts; generic Process/Queryable project their own private catalogs into those items without referencing Registry.Server/Client. `Kaleido.Registry.Server` alone owns central stores, leases, rolling-build merge, cache and opaque snapshot versions. Its in-memory store holds typed models; provider serialization is not authority behavior. `Kaleido.Registry.Client` owns only explicit opt-in publication/hydration/health; local-only hosts and reader-only participants never silently register. `Kaleido.Registry.Http` owns fixed URLs, `.Http.Server` owns ASP.NET listener/filtered discovery/weak ETags and `.Http.Client` calls those endpoints with the shared outbound credential pipeline. Never add a Registry-contracts → capability/transport reference or bring dead Platform back into a live project. Keep fixtures with each owning project; use direct TestServer to prove the authority without a participant before testing the composed client. Read [authorization](../../../docs/architecture/authorization.md) before changing caller filtering, and do not make an internal publication/source seam public merely to satisfy MA0182.
