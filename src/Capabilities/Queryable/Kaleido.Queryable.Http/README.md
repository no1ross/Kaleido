# Kaleido.Queryable.Http

HTTP request contracts and versioned logical query routes for the Queryable capability. `QueryApiRequest` / `QueryApiRequest<TParameters>` carry typed parameters and a `QueryApiBody` (search, JSON filter tree, sort and page); `QueryApiBodyExtensions.ToApiBody()` turns a CLR `QueryBody` into that wire shape with the shared `Kaleido.Http.KaleidoJsonOptions`. `QueryableContractUrls` builds the source/view routes servers publish beneath a service version. Values, JSON property names and route strings were moved from the former Platform/Http projects without changing the wire format.

The project references generic `Kaleido.Queryable` and shared `Kaleido.Http`, **not** Platform, ASP.NET, Http.Server or the central Registry. Its counterpart `Kaleido.Process.Http` will follow the same boundary: capability-owned HTTP wire shapes and URLs, with no endpoint or runtime execution logic. `QueryResult<T>` remains the response contract supplied by generic Queryable, so this project does not duplicate it. Registry-only `QueryableSourceResponse`, view/field metadata and availability/status remain in the unmigrated published Registry model until that owner is processed. Outbound clients call registry-published routes rather than deriving a destination from a prefix.

The matching `Kaleido.Queryable.Http.UnitTests` suite covers CLR-to-JSON filter/enum/date conversion, null and grouped values, and versioned source/view route generation. Mapping requests into CLR query inputs and serving local endpoints belong to [`Kaleido.Queryable.Http.Server`](../Kaleido.Queryable.Http.Server/README.md), not this wire project; that adapter runs without a central Registry client.
