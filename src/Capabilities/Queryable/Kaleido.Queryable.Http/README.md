# Kaleido.Queryable.Http

HTTP request contracts and versioned logical query routes for the Queryable capability. `QueryApiRequest` / `QueryApiRequest<TParameters>` carry typed parameters and a `QueryApiBody` (search, JSON filter tree, sort and page); `QueryApiBodyExtensions.ToApiBody()` turns a CLR `QueryBody` into that wire shape with the shared `Kaleido.Http.KaleidoJsonOptions`. `QueryableContractUrls` builds the source/view routes servers publish beneath a service version. Values, JSON property names and route strings were moved from the former Platform/Http projects without changing the wire format.

The project references generic `Kaleido.Queryable` and shared `Kaleido.Http`; its lower Registry contracts are reached through Queryable, **not** a Registry authority/client, Platform, ASP.NET or Http.Server. `AddQueryableHttpBindings()` explicitly installs the Queryable HTTP binding contributor when a host maps these endpoints: it attaches only POST source/view operation paths to the generic capability's Registry-owned `QueryableRegistryItem` descriptions, without re-projecting fields or authorization. Generic local Queryable still runs without HTTP or central participation. [`Kaleido.Process.Http`](../../Process/Kaleido.Process.Http/README.md) owns the analogous Process wire/binding contribution. `QueryResult<T>` remains generic Queryable's response contract. Outbound clients resolve published routes rather than deriving a destination from a prefix.

The matching `Kaleido.Queryable.Http.UnitTests` suite covers CLR-to-JSON filter/enum/date conversion, null and grouped values, versioned source/view route generation and HTTP-only Registry binding contribution. Mapping requests into CLR query inputs and serving local endpoints belong to [`Kaleido.Queryable.Http.Server`](../Kaleido.Queryable.Http.Server/README.md), not this wire project; that adapter runs without a central Registry client.
