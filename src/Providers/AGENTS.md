# Provider area rules

Inherit root and `src/` guidance. Providers implement or register the Process/Eventing/Registry store contracts; lower capabilities must not reference back to a provider. `Kaleido.Provider` temporarily offers explicit `AddInMemoryProviders()` registration of existing Process context, Process.Server idempotency and Eventing outbox implementations; it must not silently select memory or move their source files before #559. In-memory implementations warn when resolved and lose data on restart; durable providers retain their own transaction/store fidelity. Hosting checks **presence** of required store registrations, never rejects a store merely because it is in memory. `Kaleido.Provider.SQLite` now implements Process/Process.Server/Eventing and Registry.Server stores in one reference package (#623): preserve opaque replay bytes, typed build identities, Process state/version fidelity, conditional writes and the same scoped EF transaction for state/outbox. It never silently migrates or deletes an existing database; concurrent-writer WAL and shared in-memory SQLite remain #558. Read [dependency boundaries](../../docs/architecture/dependencies.md) and the affected provider README; validate the provider's own test pair, with pack/consumer gates deferred to the end of #585.
