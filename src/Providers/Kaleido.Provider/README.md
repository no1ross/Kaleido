# Kaleido.Provider

This temporary base project offers explicit `AddInMemoryProviders()` registration for `IProcessContextStore`, Process.Server's neutral `IProcessIdempotencyStore`, and Eventing's `IKaleidoOutboxStore`. It selects their existing in-memory implementations only when that store contract is not registered. Process, Process.Server and Eventing still own those internal concrete implementations pending #559; each warns when resolved. The state, idempotency and outbox stores are singleton per host so separate request scopes see the same in-memory data. Neither `AddProcess()` nor `AddEventing()` silently chooses a provider.

In-memory data is lost on restart, is not shared between instances, and does not make state/event writes transactional. Production hosts register durable stores in the same provider session instead. A durable `AddContextStore<T>()`, `AddIdempotencyStore<T>()` or `AddOutboxStore<T>()` may run before or after `AddInMemoryProviders()`: an earlier durable choice is retained, and a later durable choice replaces the in-memory reference registration. `Kaleido.Hosting` checks that required store contracts have *some* registration at startup, never the implementation technology. The final migration of in-memory implementations to `Kaleido.Provider.InMemory` remains in #559. See [ADR 0048](../../../docs/decisions/0048-explicit-provider-registration-without-default-stores.md), [dependency boundaries](../../../docs/architecture/dependencies.md) and the [persistence guide](../../../docs/guide/persistence.md).
