# Kaleido.Provider

This base project is a dependency bundle for the existing `IProcessContextStore` and `IProcessTransactions` in Process, neutral `IProcessIdempotencyStore` in Process.Server, and `IKaleidoOutboxStore` in Eventing. It adds no store implementation, registration extension or hidden provider choice. Concrete providers reference it; a service selects each store explicitly from a provider or registers its own implementation. The control Registry's `IKaleidoRegistryStore` belongs to Registry.Server, which a provider such as SQLite references when it implements that fourth store.

[`Kaleido.Provider.InMemory`](../Kaleido.Provider.InMemory/README.md) selects explicitly in-memory implementations for tests and local development; [`Kaleido.Provider.SQLite`](../Kaleido.Provider.SQLite/README.md) implements all four stores on SQLite (the Registry on its own database). Hosting checks only that stores required by registered work have a provider; it never chooses one or rejects memory by technology. A host selecting two different providers for the same store fails regardless of registration order. See [ADR 0049](../../../docs/decisions/0049-one-provider-per-store.md) and the [persistence guide](../../../docs/guide/persistence.md).
