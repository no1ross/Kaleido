# Foundation modification rules

Inherit the repository and `src/` guidance. Read [foundation architecture](../../docs/architecture/core.md), [dependency boundaries](../../docs/architecture/dependencies.md) and the [project README](Kaleido/README.md) before editing this project.

- `Kaleido` may not reference Eventing, Process, Queryable, Server, Provider or Hosting. `AddKaleido()` registers shared identity, logging, correlation and metadata only; never silently add a capability runtime, outbox writer, store, publisher, provider or transport. Keep `IKaleidoBuilder` minimal, assembly deduplication stable, and `TypeFilterExtensions` failure/cancellation semantics unchanged.
- Preserve configuration-over-code overlay on a **copy**, single registration validation and scoped caller/correlation accessors. Do not move `Events` back into `KaleidoServiceOptions`; Eventing binds its own `Kaleido:Events` section. `Assemblies` and `TypeFilter` stay in foundation by owner decision; authorization declarations and metadata belong to Core's `Kaleido.Registry` namespace; the mode/service default belong to the transport-neutral Server project. Keep the shared options overlay and explicit options validation stable.
- Core's internal `Replace<T>`/`RegisteredType<T>` still support explicit Process/Eventing store registration and must not be deleted without tracing those callers. Concrete `TypeDescriber`, `ConstraintMapper`, shared classification inspection and resilience value shapes affect multiple projects: inspect downstream use before changing them. Hosting checks only missing provider registrations; no store-choice contributor or in-memory default belongs in Core.
- `tests/Core/Kaleido.UnitTests` is **Core-only**: do not add Process/Queryable/Eventing project references or use their payload types as samples. Build the source/test pair with zero warnings and run the suite; follow the root #585 active-unit exception and docs/API checks before a migration commit.
