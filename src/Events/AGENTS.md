# Eventing source rules

Inherit root and `src/` guidance. Read [Eventing architecture](../../docs/architecture/events.md), [dependency boundaries](../../docs/architecture/dependencies.md) and the [project README](Kaleido.Eventing/README.md). #593 is a shallow extraction; #592 owns the separate final Eventing design.

- This package contains generic envelopes, classified-payload redaction, writer, outbox store/relay/health and opaque dispatch seams. It may reference foundation but **not** Process or Queryable; those owners define payloads/discriminators and register typed dispatch even in relay-only hosts. Do not add a fake `AddEventOutbox()` while its distinct responsibility is undecided (#592).
- One meaningful `AddEventing(options?)` binds the same `Kaleido:Events` keys over code options: malformed typed binding uses `invalid_options`, semantic validation uses `invalid_event_options`. It registers the writer and outbox health check, **not** an outbox store or publisher. `AddOutboxRelay<TPublisher>()` explicitly chooses the publishing host; `AddOutboxStore<T>()` or the temporary Provider's explicit `AddInMemoryProviders()` chooses the store (ADR 0048).
- Preserve stored event JSON, stable owner-provided discriminator strings, writer service/version tags, redaction-before-outbox, leased at-least-once relay delivery, retry/parking, relay-only dispatch and outbox health semantics. No Process/Queryable sample payload dependency in `Kaleido.Eventing.UnitTests`: use test-local data events and test their real payloads in their owner suites.
- The compatibility `<RootNamespace>Kaleido</RootNamespace>` is temporary; do not treat current placement or naming as a settled final API. Build the Eventing source/test pair and directly affected Process/Queryable pairs with zero warnings; use the root #585 active-unit and docs/API gates before a migration commit.
