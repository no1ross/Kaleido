# Kaleido.Eventing

This project owns generic event envelopes, event payload redaction, the outbox store contract and writer, relay, and outbox health checks. It depends on [`Kaleido`](../../Core/Kaleido/README.md) for identity, correlation, configuration overlay, shared classifications and the builder. It does not own Process or Queryable event payloads or discriminators, a transport, or a particular persistence technology. Process and Queryable use its neutral event seams; they define their own typed event dispatch.

Call `AddKaleido(configuration, serviceOptions).AddEventing(eventOptions)` to register the current outbox-backed event pipeline. `AddEventing` binds `Kaleido:Events` over a copy of the optional `KaleidoEventOptions` supplied in code, validates it, installs the event writer and outbox health check, but no store default. Set event redaction separately with `AddEventRedaction(...)` or `AddEventRedactor<T>()`. Choose an outbox store with `AddOutboxStore<T>()`, [`AddInMemoryOutboxProvider()`](../../Providers/Kaleido.Provider.InMemory/README.md) for development or a durable provider; a different second choice conflicts in either order. The writer does not register a publisher; one host per outbox database calls `AddOutboxRelay<TPublisher>()` to publish stored entries at least once.

A relay-only host registers the Process and Queryable event dispatchers it needs (`AddProcessEventDispatch()` and `AddQueryableEventDispatch()`) without starting either runtime. Eventing treats a stored discriminator and payload as opaque until the registered owner dispatches it. The event payload's JSON and the existing discriminator values must remain stable through this extraction.

This is a **shallow, temporary** package boundary. Existing namespaces and the project's `<RootNamespace>Kaleido</RootNamespace>` are preserved for compatibility; #592 decides the final Eventing layer and whether `AddEventOutbox()` has a distinct responsibility. No no-op registration API is created. For architecture see [Eventing and the outbox](../../../docs/architecture/events.md) and [dependencies](../../../docs/architecture/dependencies.md); the [event guide](../../../docs/guide/events-and-outbox.md) covers usage and the [outbox decision](../../../docs/decisions/0036-stores-scoped-by-service-and-a-shared-outbox-relay.md) records delivery guarantees.
